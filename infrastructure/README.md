
# Infrastructure Layer (Edge Nginx)

The `infrastructure/` directory contains the **Edge Reverse Proxy** — a single, unified entry point for the entire platform. It sits in front of both the **CnSS** (backend) and **MUI** (frontend), handling TLS termination, secure routing, and static file serving.

## Purpose

Instead of each service (CnSS and MUI) managing its own TLS certificates and external ports, this layer centralizes all external-facing concerns:

- **TLS Termination**: A single SSL certificate secures both `https://` and `wss://` traffic.
- **Unified Routing**: One port (`443`) exposes the entire platform to clients.
- **Static File Serving**: The MUI build output is served directly by Nginx, eliminating the need for a separate frontend container in production.
- **Security Boundary**: Internal microservices remain isolated in Docker networks, unreachable from the outside without passing through this proxy.

## Architecture

```
                          ┌─────────────────────────────────────┐
  Client (Browser)        │      Infrastructure Layer           │
  ──────────────────────▶ │      (Edge Nginx :443)              │
   https:// / wss://      │                                     │
                          │   /           → MUI static files    │
                          │   /api/*      → CnSS REST API       │
                          │   /ws/*       → CnSS WebSocket      │
                          └─────────────────────────────────────┘
                                        │
                          ┌─────────────┼─────────────┐
                          ▼             ▼             ▼
                     ┌────────┐   ┌──────────┐   ┌────────────┐
                     │  MUI   │   │ CnSS API │   │ CnSS WS    │
                     │(static)│   │  :8000   │   │  :8000     │
                     └────────┘   └──────────┘   └────────────┘
```

## Directory Structure

```
infrastructure/
├── nginx/
│   ├── certs/                  # TLS certificates (gitignored, generated by `make certs`)
│   │   ├── fullchain.pem       # Public certificate (served by Nginx)
│   │   ├── privkey.pem         # Private key (never commit this!)
│   │   └── cnss-local.crt      # Copy for distribution to LAN clients
│   └── nginx.conf              # Edge Nginx configuration
├── docker-compose.infra.yml    # Docker Compose for the Edge proxy
├── Makefile                    # Automation commands
└── README.md                   # This file
```

## Prerequisites

Before starting the Infrastructure layer, the following conditions **must** be met:

### 1. CnSS Backend Must Be Running

The Edge Nginx proxies requests to the CnSS microservices via the `cnss-network` Docker network. Ensure CnSS is up and healthy:

```bash
cd ../cnss
make prod
```

Verify that the following containers are running:
- `cnss-api`
- `cnss-websocket`

### 2. MUI Static Files Must Be Built

The Edge Nginx serves the MUI frontend directly from a volume. The production build of MUI must exist before starting Nginx:

```bash
cd ../mui
npm ci && npm run build
```

The built files should be available at `../mui/dist/`.

> **Note**: If you are using the unified `Makefile` at the repository root, the `make prod` command should handle this dependency automatically.

### 3. Docker Networks Must Exist

The Edge Nginx connects to the external Docker networks created by CnSS (`cnss-network`). These networks are created automatically when you run `make prod` in the CnSS directory.

### 4. TLS Certificates Must Be Present

Nginx will **fail to start** if the TLS certificates are missing. Generate them first:

```bash
make certs
```

## Quick Start

```bash
# 1. Generate self-signed TLS certificates (if not already done)
make certs

# 2. (Optional) Install the certificate into your system's trust store
#    Arch Linux:
sudo cp ./nginx/certs/cnss-local.crt /etc/ca-certificates/trust-source/anchors/cnss-local.crt
sudo trust extract-compat

# 3. Start the Edge Nginx
make up

# 4. Verify the deployment
make status
make test-ssl

# 5. Access the platform
#    Open https://localhost in your browser
```

## Available Commands

Run `make help` to see all available commands. The most important ones are:

### Certificate Management

| Command            | Description                                                                 |
|--------------------|-----------------------------------------------------------------------------|
| `make certs`       | Generate a self-signed TLS certificate for `localhost` and `127.0.0.1`.     |
| `make serve-certs` | Start an HTTP server on port `9000` to distribute the certificate to LAN clients. |
| `make clean-certs` | Remove all generated certificates.                                          |
| `make test-ssl`    | Verify that Nginx is serving the certificate correctly on port `443`.       |

### Container Management

| Command        | Description                                              |
|----------------|----------------------------------------------------------|
| `make up`      | Start Edge Nginx in detached mode (auto-generates certs if missing). |
| `make down`    | Stop and remove the Edge Nginx container.                |
| `make restart` | Restart Edge Nginx (useful after editing `nginx.conf`).  |
| `make logs`    | Follow Edge Nginx logs in real-time.                     |
| `make status`  | Show the status of infrastructure containers.            |

## TLS Certificate Management

### Local Development

For local development, self-signed certificates are sufficient. The `make certs` command generates a certificate valid for 1 year, covering:
- `localhost`
- `127.0.0.1`
- `*.local`

To avoid browser security warnings, install the certificate into your system's trust store:

**Arch Linux:**
```bash
sudo cp ./nginx/certs/cnss-local.crt /etc/ca-certificates/trust-source/anchors/cnss-local.crt
sudo trust extract-compat
```

**Windows:**
1. Open `http://<server-ip>:9000/cnss-local.crt` in your browser (run `make serve-certs` first).
2. Double-click the downloaded file.
3. Click **Install Certificate** → **Local Machine** → **Next**.
4. Choose **Place all certificates in the following store** → **Browse** → **Trusted Root Certification Authorities**.
5. Click **OK** → **Next** → **Finish** → **Yes** (confirm the security warning).

**macOS:**
```bash
sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ./nginx/certs/cnss-local.crt
```

### Distributing Certificates to LAN Clients

To allow other devices on your local network to access the platform securely, distribute the public certificate:

```bash
make serve-certs
```

This starts a simple HTTP server on port `9000`. Clients can download the certificate at:

```
http://<your-server-ip>:9000/cnss-local.crt
```

> **Important**: The certificate is served over **HTTP** (not HTTPS) intentionally. Clients need the certificate *before* they can trust HTTPS connections — this breaks the chicken-and-egg problem.

### Production Certificates

For production deployments, replace the self-signed certificate with a certificate from a trusted Certificate Authority (e.g., Let's Encrypt). Place the following files in `./nginx/certs/`:

- `fullchain.pem` — The full certificate chain (your cert + intermediate CA).
- `privkey.pem` — The private key.

Then restart Nginx:

```bash
make restart
```

## Troubleshooting

### Nginx fails to start with `cannot load certificate`

The TLS certificates are missing. Run:

```bash
make certs
make up
```

### Browser shows `ERR_CERT_AUTHORITY_INVALID`

The self-signed certificate is not trusted by your system. Install it into your trust store (see [TLS Certificate Management](#tls-certificate-management)).

### 502 Bad Gateway when accessing `/api/` or `/ws/`

The CnSS backend is not running or not reachable. Verify:

```bash
cd ../cnss
docker compose ps
```

Ensure `cnss-api` and `cnss-websocket` are `Up` and `healthy`.

### WebSocket connection fails

Check that:
1. The URL uses `wss://` (not `ws://`).
2. The certificate is trusted by your browser.
3. The CnSS WebSocket service is running.

## Security Notes

- **Never commit** the `./nginx/certs/` directory to version control. It is already listed in `.gitignore`.
- The private key (`privkey.pem`) must have restricted permissions (`600`). The `make certs` command sets this automatically.
- For production, always use certificates from a trusted CA. Self-signed certificates are suitable **only** for local development and testing.
- The Edge Nginx masks JWT tokens in access logs to prevent credential leakage (see `nginx.conf`).
